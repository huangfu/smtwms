# SMT-WMS 核心业务 SOP 与领域红线

## 1. 适用场景
- 修改或新增收料流程（预约登记、到货签到、扫码收料、IQC 质检、入库上架、库存更新、信息同步）。
- 修改波次发料、产线补料/退料、MSD 烘烤/暴露计时、物料产权与客户隔离逻辑。
- 新增 MRB 不良隔离、退供应商（RTV）、超收管控、盘点盈亏等仓储领域规则。

## 2. 不可违背的业务红线（MUST）

### 2.1 收料 7 阶段严格职责分离
标准单向流转路径：
`1. 供应商送货` → `2. 预约登记(ASN)` → `3. 收料登记` → `4. IQC质检` → `5. 入库上架` → `6. 库存更新` → `7. 信息同步`

- **预约与收料阶段禁止出现 IQC 判定**：
  - 预约登记（ASN 制单）、到货签到、扫码收料登记阶段，**严禁**出现 `IQC 合格 / IQC 不良` 选项。
  - 收料员只核收实到数量，点收完成的物料行保持 `iqcStatus = 'PENDING'`、`iqcPassedQty = 0`，不可直接入良品库。
- **IQC 前置门禁**：
  - 只有当 ASN 全部明细完成点收登记（`receivedQty >= expectedQty`）后，才允许进入 `IQC_INSPECTION` 阶段；未收齐前调用 IQC 接口或操作必须拦截报错。
- **支持三种 IQC 判定结果**：
  - 整行合格放行、整行不良隔离、以及**单行拆分判定**（`passedQty + rejectedQty <= 待检余量`，可附检验/不良备注）。
- **不良品严禁进入入库上架**：
  - 上架前置门禁：未完成全部行 IQC 判定前，禁止上架。
  - 上架目标数量严格等于 `iqcPassedQty`（严禁使用 `expectedQty` 或 `receivedQty`）。
  - **整行不良物料（`iqcPassedQty <= 0`）必须从上架队列（已刷/作业中/未刷）彻底剔除**：不得渲染为 `0 / 0 已上架入库`，不得分配良品库位，不得生成 `IN_STOCK` 料盘。
  - 整单 100% 不良时，跳过上架直接闭环生成 MRB 退供流水，不产生良品库存。
  - 任何快捷入库入口关联 ASN 时，同样必须校验并拦截已判 IQC 不良的物料行。

### 2.1.1 三权分立与跨部门异步通知解耦（采购 / 仓库 / IQC）
来料全链路严格按部门职权物理隔离（由 `src/utils/roleAccess.ts` 作为单一权限真源控制）：
- **采购部（`PROCUREMENT`）独享 ASN 计划权**：
  - 仅采购视角可创建、CSV 导入和管理预约送货单（`asnPlan`），仓库菜单、仓库看板预警弹窗、无单急料入库及仓库空状态**严禁**出现「新建 ASN / 导入 ASN / 下达采购补货 ASN」入口。
  - 采购 ASN 管理台仅展示下游履约只读进度（待仓库初收 / 已通知 IQC 待检 / IQC 已放行待入库 / 已入库 / IQC 不良退供），**严禁**在采购界面提供「按此 ASN 收料」等越权仓库执行按钮。
- **仓库部（`WAREHOUSE`）独享待收料初收与合格品入库上架权**：
  - 仓库仅看到采购下发的「待收料清单」（`1. 到货签到`、`2. 待收料初收`）以及 IQC 放行后的「合格品待入库清单」（`3. 合格品入库上架`）。
  - 仓库完成初步收料登记后，系统自动更新批次状态并发送**异步「IQC 报检通知」**，页面停留在仓库待收料界面并显示已报检通知回执，**严禁**自动跳转或提供直达按钮进入 IQC 质检页。
  - 仓库 PDA 菜单与侧边栏**严禁**挂载 `IQC 来料质检` 或 `ASN 预约登记`。
- **IQC 品质部（`IQC`）独享来料检验判定权**：
  - IQC 仅看到仓库完成初收并报检的「IQC 报检待检清单」（`asnIqc`），执行合格/不良/拆分判定。
  - IQC 全部行判定放行后，系统自动发送**异步「合格品放行通知」**回传仓库部待入库清单，页面停留在 IQC 作业区并显示放行通知回执，**严禁**自动跳转或提供直达按钮进入仓库上架页。

### 2.2 电子料仓通用硬防呆规则
- **FIFO 先进先出**：波次分配与发料扫码严格按 `DateCode` 升序 + `receivedAt` 升序锁定；扫入更新周期料盘必须触发 `FIFO防错拦截`。
- **MSD 湿敏管控**：`BAKING_REQUIRED`（暴露超时未烘烤）料盘严禁参与波次分配、出库与产线补料；烘烤复位后方可解锁。
- **客户与产权隔离**：
  - 物料主数据按 `(skuCode + ownershipType + ownerCode + customerCode)` 复合唯一键管理。
  - 客供料与指定客户专备自购料，严禁分配或补料到其他客户工单。
  - BOM 中的 `SUBSTITUTE`（替代料）行不得重复计入波次净需求。

## 3. 禁止的反模式（DON'T）
- ❌ **禁止把两个不同岗位的动作塞进同一个状态或表单**（如：收料点收时顺手点 IQC 合格）。
- ❌ **禁止破坏部门职权分离**：严禁在仓库画面暴露 ASN 建单/导入功能；严禁在采购画面提供仓库收料按钮；严禁仓库与 IQC 页面之间出现自动跳转或直达切换按钮（必须通过异步报检/放行通知队列解耦）。
- ❌ **禁止用 `targetQty === 0 ? 'SCANNED'` 的短路逻辑**：这会把 0 合格数的不良品误判为“已完成上架”。
- ❌ **禁止仅在前端隐藏按钮而不做领域层/后端拦截**：所有前置门禁与不良拦截必须在领域纯函数（`src/utils/wmsLogic.ts`、`src/utils/roleAccess.ts`）和后端接口中双重抛出明确业务错误。
- ❌ **禁止修改核心规则后不补单元测试**：每次新增/修改状态流转、权限隔离或拦截规则，必须同步补齐单元测试覆盖正常路径与异常拦截路径。
