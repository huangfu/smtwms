# 工业 PDA 单功能扫码作业 UI 规范

## 1. 适用场景
- 新增或改造面向仓库作业员、IQC 检验员、产线物料员的重复性扫码作业页面。
- 优化移动端（360px ~ 414px，基准 `390×844`）PDA 首屏利用率与防误触体验。

---

## 2. 核心设计铁律（MUST）

### 2.1 一功能一页面（Single-Function Page）
- **严禁把多道工序堆在同一页面**：每个独立作业环节必须是独立菜单项与独立全屏作业页（例如：`1. 到货签到`、`2. ASN扫码收料`、`3. IQC来料质检`、`4. 合格品入库上架`）。
- **PDA 首页磁贴导航**：移动端默认进入大磁贴单功能启动台，显示各工序实时待办单据数，一键直达作业页；顶部提供明确返回按钮（`aria-label="返回 PDA 作业菜单"`）。
- **工序完成自动跳页**：当本工序全部明细完成时，自动推进状态并跳转至下一工序独立页面，顶部展示绿色流转提示条告知作业员已自动衔接。

### 2.2 连续扫码 + 无码人工兜底
- **主扫码框置顶且高对比**：输入框高度不低于 `48px`，支持扫描枪模拟键盘输入后直接 `Enter` 提交，提交完成自动清空并重新聚焦（`scanInputRef.current?.focus()`）。
- **自动匹配物料与数量**：扫箱上 2D 条码自动按供应商条码规则解析 `MPN / Lot / D/C / Qty`，自动匹配清单行、累加数量并更新进度与状态；不在清单内的料号立即红框报错。
- **无箱码人工补录兜底**：提供折叠式「无箱码？人工录入」面板，允许选择明细行手填数量/批次/周期，不阻塞异常来料现场作业。

#### 2.2.1 统一扫码区组件契约（Mandatory `<PdaScanField />` Contract）
**硬性要求**：全站所有涉及“扫码 / 条码录入 / UID 定位”的作业页面（包括但不限于：ASN 扫码收料、IQC 来料质检、合格品入库上架、无 ASN 急料入库、波次扫码发料、其他领料出库、SMT 产线补料、产线余料退库、物料报废隔离、循环盘点扫码、全程扫码追溯），**必须统一复用 `src/components/PdaScanField.tsx`**，严禁在各业务页面手写普通 `<input>` 或纯 `<select>` 冒充扫码框。

统一视觉与交互 Token（MES 方案 B · 深碳导航 + 浅灰作业区 + 深海工业青）：
- **外层作业面板**：统一使用 `.mes-panel`（`#FFFFFF` 表面 + `#E2E8F0` 边框 + 轻微层次阴影，严禁“卡片内再套灰色小卡片”）。
- **扫码框视觉标识（全站 100% 一致）**：
  - 左侧固定 `ScanBarcode` 图标（`text-teal-700/80`）。
  - 输入框强制 `min-h-[48px]`、`border-2 border-teal-600/80`、`font-mono text-sm`、聚焦态 `focus:border-teal-700 focus:ring-2 focus:ring-teal-600/20`。
  - 标题或字段 Label 左侧统一带 `ScanBarcode` 图标（`text-teal-700`），附简明副标题说明扫码范围或防呆规则。
- **主操作按钮（触控一致）**：
  - 高度强制 `min-h-[48px]`、`font-semibold`；禁用态统一 `disabled:bg-slate-200 disabled:text-slate-500`（保证对比度达标且无虚化发灰感）。
  - 仅在语义动作按钮上区分状态色（常规确认 `teal-700`、IQC 合格 `emerald-700`、IQC 不良/报废 `red-600/700`），**扫码框本身的 2px 深海青扫描边框全站保持绝对统一**。
- **复合条码自动解析与快捷点选**：
  - 扫码框同时支持直接输入 UID、`<datalist>` 下拉备选、以及扫描原厂复合码（`UID:...|P:...` / `;` / `|` 分隔）自动提取料盘 UID。
  - 下方可选配最多 3~4 个单手可点快捷码按钮（`min-h-[36px] font-mono`），方便现场调试与高频点选。

#### 2.2.2 扫码完成后标准作业逻辑（Mandatory Post-Scan Lifecycle）
所有扫码作业必须统一调用 `src/utils/pdaScanFocus.ts`（`completePdaScan` / `focusScanInputOnMount`），确保扫描枪“盲扫连续作业、零手工介入 UI”：
1. **进入页面 / 切换单据或阶段**：主扫码框自动获得焦点（若带默认值则自动全选，保证扫码枪直接覆盖而不拼接）。
2. **业务处理成功（`outcome: 'success'`）**：
   - 自动**清空**扫码输入框；
   - 自动**重新获得焦点**，立即等待下一次扫描；
   - 页面中关联的显示数据（清单、3-Tab 计数、流水台账、条码解析带出的表单字段或追溯结果卡片）**自动实时更新**，不因清空输入框而丢失当前结果展示。
3. **业务处理失败（`outcome: 'error'`）**：
   - **保留**上次刷入的原始条码数据（便于作业员核对错码），同时在**扫码框正下方**就近展示清晰 `role="alert"` 红框原因提示；
   - 自动**全选内容（`.select()`）并保持焦点（`.focus()`）**，同时调用 `scrollIntoView({ block: 'center', behavior: 'smooth' })` 确保浏览器视口自动回正到扫码区，作业员处理完异常后直接扣动扫描枪即可覆盖重扫，**严禁要求作业员手动点击清空、滚屏找错误或重新点框**。

#### 2.2.3 扫码错误与结果就近反馈规范（Inline Zero-Scroll Feedback & Error-Frame Linkage）
PDA 均通过移动端浏览器访问（`390×844`，不打包原生 APK），作业员视线始终停留在顶部扫码框附近，必须保证**“零滚动即可一眼看清错因与结果”**：
1. **强制就近展示（紧贴输入框正下方）**：
   - 所有扫码与表单提交产生的错误提示（`role="alert"`）和成功反馈（`role="status"`），必须通过 `<PdaScanField feedback={{ type: 'error' | 'success', message, action }} />` 内置插槽，渲染在**扫码输入框正下方、快捷点选按钮之前**。
   - **严禁将错误或成功提示放在表单最底部提交按钮上方**（在 390×844 竖屏中会被表单字段挤出首屏，导致作业员扫码失败却看不到原因）。
2. **扫码框视觉错态联动（2px 告警红框）**：
   - 当 `feedback.type === 'error'` 时，`<PdaScanField />` 自动将输入框边框与左侧 `ScanBarcode` 图标切换为 **2px 告警红**（`border-red-600 focus:border-red-700 focus:ring-red-600/20`、`text-red-600`），并附带 `aria-invalid="true"` 与 `aria-describedby` 关联错误提示条。
   - 作业员一修改或重新刷入条码（`onChange`），必须立即清除旧错误状态，扫码框瞬间恢复 **2px 深海工业青** 待扫状态。
3. **跨屏提交失败自动回滚到扫码区**：
   - `src/utils/pdaScanFocus.ts` 在重新聚焦扫码框时统一执行 `scrollIntoView({ block: 'center', behavior: 'smooth' })`，即使作业员向下滚动点击底部提交按钮触发校验失败，浏览器也会自动平滑回正到顶部的红框扫码区与紧贴其下的错误原因条。

### 2.3 底部固定三态进度分组（3-Tab）
所有重复性扫码清单统一采用底部 3-Tab 分组切换：
1. **`已刷 (N)`（默认选中）**：本环节已 100% 完成的物料行（每次切换单据或阶段推进后重置为默认 `已刷`）。
2. **`作业中 (N)`**：部分扫描/部分完成的物料行，明确显示剩余待作业数量。
3. **`未刷 (N)`**：尚未开始作业的物料行，提供快捷操作按钮（如无码人工录入、一键质检、一键上架）。
- **空态引导**：当默认 `已刷 (0)` 且 `未刷` 或 `作业中` 有待办项时，提供一键跳转至待作业 Tab 的大按钮。

### 2.4 手持触控与首屏密度约束
- 所有可点击按钮与输入框最小触控高度 `>= 44px`（核心扫码框与主提交按钮强制 `>= 48px`）。
- 移动端严禁横向溢出（无水平滚动条）；长文本/单号做好 `truncate` 或换行处理。
- 顶部单据选择区压缩在 1 个紧凑卡片内，确保 **390×844 首屏同时可见：当前单号 + 步骤进度 + 主扫码框 + 3-Tab 进度条**。
- 可访问性规范：使用原生 `<button>`、`<select>`、`<input>` + `<label>`、`role="tab"`、`role="status"`、`role="alert"`，禁止用 `<div>` 冒充可点击按钮。

## 3. 禁止的反模式（DON'T）
- ❌ **禁止手写非标准 `<input>` 充当扫码框**：严禁出现 `border border-slate-300` 无图标普通输入框或只有 `<select>` 下拉框却标注“扫描料盘 UID”的风格割裂问题；必须使用 `<PdaScanField />`。
- ❌ **禁止把错误/成功提示藏在表单底部**：严禁在表单提交按钮上方单独渲染远离扫码框的错误提示条，必须接入 `<PdaScanField feedback={...} />` 保证 390×844 首屏零滚屏可见。
- ❌ **禁止卡片套卡片**：不要在 `.mes-panel` 内再包裹多层 `bg-slate-50 border rounded-md` 嵌套盒子放扫码框，改用细分割线与留白分层。
- ❌ **禁止把 PC 多列宽表格直接塞进 PDA 作业页**：PDA 清单必须使用纵向信息卡片，关键数据分层排版。
- ❌ **禁止把被前序环节拦截/剔除的物料混进 3-Tab 卡片中**：被剔除项只能以顶部独立提示条说明，不占 3-Tab 计数。
- ❌ **禁止隐藏非当前阶段拦截提示**：若作业员在某单功能页选中了尚未到达本阶段的 ASN，必须显示清晰引导卡片与「前往对应阶段页面」的一键按钮。
