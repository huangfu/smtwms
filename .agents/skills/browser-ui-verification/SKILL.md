# 通用工程技能：真实浏览器 UI 交互与视觉验收闭环

## 1. 适用场景
- 新增页面、表单、弹窗、移动端/PDA 适配界面，或修复任何可见的 UI/状态联动缺陷。
- 纯后端逻辑、纯文档或纯配置改动可跳过浏览器截图，仅运行单元测试与构建即可。

---

## 2. 编码阶段：让页面天生可测试（MUST）
- **使用原生语义化 HTML**：`<button>`、`<a href>`、`<input>` 配 `<label htmlFor>`、`<select>`、`role="tab"`、`role="status"`、`role="alert"`。严禁用 clickable `<div>` 替代按钮。
- **控件命名清晰唯一**：所有图标按钮必须提供准确的 `aria-label`；避免同一屏出现多个无区分的同名按钮。
- **状态端到端真实联动**：点击提交后必须真实更新底层状态、列表计数、标签分组与路由，禁止只弹一个静态 Toast 假装成功。

---

## 3. 浏览器实测与缺陷分级审查（MUST）

### 3.1 验收步骤
1. 编译并通过单元测试后，重启/刷新开发服务，确保浏览器加载最新构建产物（避免看缓存旧代码）。
2. 按目标用户视口实测：
   - 桌面管理端：`1440×900`
   - 手机 / 工业手持 PDA：`390×844`
3. 跑通 1~3 条核心端到端用户旅程（包含表单提交、状态流转、空态与报错拦截），检查浏览器控制台与网络请求是否有未预期报错。
4. 对关键视觉状态截图审查（不要只依赖 DOM 文本，很多遮挡/截断/溢出只有看图才能发现）。

### 3.2 缺陷优先级标准
- **高危（必须修完复验）**：核心流程走不通、JS 运行时异常、API 报错、文字不可读/重叠/被裁切、横向滚动条溢出、业务状态显示错误（如不良品显示为已入库）。
- **中危（尽量顺手修）**：信息层级混乱、间距不统一、移动端触控目标过小（`< 40px`）、缺少空态引导。
- **忽略（勿浪费轮次）**：无害的 `favicon.ico` 404、已生效的降级提示日志。

---

## 4. 交付汇报纪律
- 如实汇报**实际跑通了哪些测试用例、哪些视口和哪些交互步骤**。
- 严禁声称验证了自己并未实际执行或查看过的页面与功能；若有未验证项，直接说明原因。
